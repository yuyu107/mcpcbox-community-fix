# MCPCBox Community Fix v7.0

项目在此前修复工作的基础上恢复维护，本次以 **v7.0** 发布。相较上一公开版本 **v6.5**，这次重点更新游戏版本获取、下载管理与页面交互。

发布标签使用 `v7.0`，附件为 `MCPCBox_Community_Fix_v7.0.zip`。本次附件对应内部构建 Native Adapter v19，已包含下载记录持久化修复。

## 相较 v6.5，新增和改进了什么？

| 项目 | v6.5 | v7.0 |
| --- | --- | --- |
| 游戏版本列表 | 使用 GitHub Pages 上的兼容清单，已实测恢复 Minecraft 1.7.10 在线安装与启动 | 动态读取 Mojang 官方版本目录，支持搜索、正式版/快照等分类、排序与分页 |
| 安装内容获取 | 通过兼容引导 ZIP 恢复旧安装链路，客户端由盒子从官方获取，首次启动再补齐语言资源 | 按官方元数据规划客户端、依赖与资源文件，下载时完成校验、原生库解压和资源映射 |
| 下载进度 | 沿用原有资源下载与安装流程 | 将一个完整版本的多文件任务汇总为一条下载中心任务，按全部文件的总字节数显示进度 |
| 重试与重复安装 | 主要沿用原资源下载、校验及安装机制 | 增加按官方 SHA-1 和大小校验的共享缓存，重试、重装及跨版本可复用相同内容 |
| 已下载页面 | 原有下载记录界面 | 新增多选、批量仅删除记录、独立操作提示框；保留普通资源文件删除，并将已安装版本卸载交给游戏管理 |
| 完成记录保存 | 沿用原下载记录机制 | 为整体版本任务增加持久化，重启后恢复；仅清记录或清空后不会重新出现 |
| 下载页面 | 兼容纯净版条目与原安装入口 | 新增官方目录页面，默认折叠说明，按钮显示准备中/下载中，结束提示支持关闭 |
| 首次中文设置 | 已为恢复的 1.7.10 安装链路提供首次简体中文 | 扩展到新安装流程，按官方语言资源区分旧版 `zh_CN` 与新版 `zh_cn`，已有 `options.txt` 保留 |

**v6.5 已经使用盒子自身下载官方客户端，并已提供首次中文设置。** v7.0 改进的是完整版本多文件下载的接入方式、统一进度、缓存复用和适用的新安装流程。本地游戏导入、管理与启动也是原版已有能力。

此前的 Java 下载地址、兼容 JSON、精彩视频、游戏直播、贴吧和关于页等修复属于旧版本工作，不重复计入本次新增功能。

## 新下载流程的完善

本轮开发中还处理了以下问题：

- 按原生任务 ID 匹配回调，避免同一路径重试时，旧任务迟到的回调干扰新任务。
- 等待原任务退出活动表后再校验、发布缓存或重试，避免重叠处理同一临时文件。
- 校验、复制和发布遇到短暂文件占用时有上限地等待，保留 SHA-1 与大小校验。
- 先同步下载中心，再公布网页结束状态；失败任务不再计入“下载中”。
- 增加缓存/安装阶段日志，便于继续定位实机下载失败。
- 修复整体版本的已完成记录重启后消失：完成时保存，启动时恢复；仅删除记录与清空操作也同步保存。恢复的记录保留名称、目录和大小，可继续打开目录。

这些是新下载流程在本轮测试中的修正，不代表上述问题在 v6.5 中都存在。

## 下载、目录与缓存

游戏文件仍由盒子的 `CDownloadManager / taskmodulehttp.dll` 从官方地址下载，不需要额外安装下载插件。新页面的本机接口内嵌在 EXE 中，监听 `127.0.0.1:19481`，随盒子运行；v6.5 原链路“无需本地 HTTP 服务”的说明不适用于新页面。

目录跟随盒子设置。若下载根目录为 `D:\MCBox\download`：

| 用途 | 位置 |
| --- | --- |
| 共享文件缓存 | `resources\official\objects` |
| 官方元数据缓存 | `resources\official\metadata` |
| 每版本缓存索引 | `resources\official\versions\<版本号>` |
| 已安装游戏 | `game\<版本号>\.minecraft` |

缓存与安装文件采用独立副本，主要减少重复下载，会增加磁盘占用及校验、复制工作，不保证首次下载更快。共享缓存暂不支持按单个版本回收。

下载中心负责记录与下载资源；卸载已安装版本请使用游戏管理。“仅删除记录”会保留文件，普通资源的文件删除限定在配置的 `resources` 目录中。已成功完成的整体版本记录保存到 `%APPDATA%\duowan\mcpcbox\community-fix\completed-history-v1.json`，重启后恢复；仅删除记录或清空后不会重新添加。缓存文件也可跨重启复用。

此前已经随旧进程丢失的汇总记录不会通过扫描游戏目录自动重建。重新选择相同版本下载时，可校验复用完整文件并生成记录。暂停、失败或取消的任务不会作为成功记录恢复。

## 更新方法

1. 下载 `MCPCBox_Community_Fix_v7.0.zip`，完全退出盒子并备份原 `MCPCBox.exe`。
2. 用包内 `MCPCBox.exe` 覆盖原程序，保留现有 DLL、游戏文件和缓存。
3. 重新打开盒子，在游戏下载页面选择版本，在下载中心查看整体进度。

这是替换主程序的更新包，需要配合已有盒子安装文件使用，包内附 `Source-v7.0.zip` 和本地验证结果。当前发布附件为包含记录持久化修复的内部 v19 构建。重建该附件请使用包内 `Source-v7.0.zip` 或主分支的 `src/native-v19/`；GitHub 自动生成的 Source code ZIP/TAR 对应 v7.0 标签创建时的源码快照，可能不含这一修复。

## 测试范围与已知问题

- 已通过页面状态回归、真实主机临时文件/SHA-1 测试，以及原入口、重定位、回调、下载中心投影和版本登记等机器码模拟回归。记录存储另通过独立进程测试，覆盖完成后重开、删除/清空后重开、中文与大文件大小、保存失败重试及损坏文件保留。
- 测试中的 Windows/原组件 API 使用替身；真实 Windows 下载稳定性、内嵌 IE、断点续传和首次启动仍需实测，尚不能确认所有下载失败原因已解决。发布不代表上述实机验证项目已经全部完成。
- 获取某个官方版本不代表旧启动器一定能启动它；仍受启动参数、Java、操作系统、显卡及游戏自身要求限制。尤其不能把 v6.5 对 1.7.10 的启动实测推广为全部新版本已通过验证。
- 此前 360 告警尚未解决，未经过安全厂商复核。

若仍下载失败，请附上版本号和 EXE 同目录 `MCPCBox-native-download.log` 的末尾，包含 `Native retry`、`Cache/install failure` 与 `Version` 汇总。
