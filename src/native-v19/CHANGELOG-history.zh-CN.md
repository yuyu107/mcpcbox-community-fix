# v7.0 已完成下载记录持久化修正

内部构建编号：Native Adapter v19。公开版本仍为 v7.0。

此前完整版本任务的汇总条目只存放在进程内存中，重启盒子后自然消失。本次为这些条目增加单独的用户配置文件：

`%APPDATA%\duowan\mcpcbox\community-fix\completed-history-v1.json`

- 完整版本任务完成时保存记录，再公布网页结束状态。
- 原下载管理器初始化后，在后台恢复成功完成的汇总记录，并刷新下载中心；页面请求也会触发补充加载。
- 保存并恢复原记录 ID、名称、缓存目录和 64 位文件大小，恢复的记录可以继续打开目录或仅清记录。
- 批量仅删除记录后同步写入；清空时保存空列表，重启不会重新出现。不会扫描游戏目录或缓存来重建已经删除的条目。
- 新任务编号避开恢复的 ID；重复加载不重复添加，也不会覆盖当前进程中已删除的记录。
- 使用临时文件、FlushFileBuffers 和同目录原子替换。写入失败会提示并保留待保存状态，后台可重试；损坏、格式不兼容或不可读的配置文件不会被空列表自动覆盖。
- 仅保存成功完成的整体任务。暂停、失败或取消的任务不作为成功记录恢复。普通资源的历史仍由原下载模块管理。

这是元数据持久化修正，不更改共享缓存或已安装游戏的目录，也不在清理记录时删除游戏文件。此前已随旧进程丢失的记录无法自动恢复；重新选择相同版本下载时，可校验复用完整文件并生成新记录。

## 验证

生产记录编解码与存储策略通过多个独立进程配合真实主机临时文件测试：完成后重开、中文/引号/64位大小、删除单条与清空后重开、重复加载、保存失败后重试、保存期间新变化再写入、损坏文件保留。

原生适配机器码在首选与重定位地址下验证了恢复记录的快照、目录读取、ID 冲突处理、重复导入和删除后去重；此前的回调、入口、缓存、页面及语言回归通过。

这些测试使用 Windows/原组件 API 替身；真实 Windows AppData 写入、盒子退出/启动和嵌入式页面刷新仍需实机验证。此前 360 告警仍未解决。
