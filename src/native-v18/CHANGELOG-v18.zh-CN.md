# v18：回调、文件收尾和下载中心状态修正

针对 v17 实测反馈的失败增多、网页结束后下载中心仍显示下载中的问题，修正以下可在代码中复现的时序风险。未取得用户失败日志，不能把所有实机失败归因于同一个原因。

- **旧回调影响新任务**：原先查找请求时，路径匹配与任务 ID 匹配混在同一次遍历。重试复用目标路径时，旧原生任务的迟到回调可能匹配到新请求并覆盖它的原生 ID/结果。现在优先匹配原生 ID；仅尚未绑定 ID 的请求允许按路径绑定，已结束或已取消请求的结果不被后续回调改写。
- **完成回调早于内部收尾**：已核对原 EXE 的 DownloadSuccess：它先发回调，再把 DownloadSuccessHandler 排入原下载线程。现在在校验、发布缓存和重用目标之前，等待旧任务从原管理器的实际活动表中退出。失败/取消后等待原线程完成移除；超时报告错误，不让重试同时写同一路径。
- **短暂文件占用**：SHA-1 校验、缓存发布和安装复制遇到 Windows 共享冲突、锁冲突或访问拒绝时，以 50ms 间隔等待，最多重试 3 秒。大小/哈希不符、缺失文件、磁盘满等不按文件占用重试。取消会打断等待，完整缓存保留原校验机制，不降低校验要求。
- **下载中心与网页结束顺序**：先更新整体任务状态，并同步通知原下载中心的两个观察者，再发布网页的结束状态。刷新请求最多等待 2 秒；超时会记录日志并显示刷新提示，不影响后续 UI 请求。
- **失败仍算下载中**：失败整体任务不再留在活动列表、占用下载计数；它也不会被当成成功记录放入已下载页。失败原因留在游戏下载页，可关闭或重新下载。
- **诊断**：增加缓存/安装阶段的文件名及错误日志。若仍失败，请保留 EXE 同目录下的 MCPCBox-native-download.log，尤其是最后一段 Native retry、Cache/install failure 和 Version 汇总。

v17 的提示框、按钮状态、默认折叠说明及首次中文设置保留。游戏文件继续调用原 CDownloadManager / taskmodulehttp.dll。

## 本地验证

- 原生适配机器码在首选和重定位地址下通过：同路径迟到回调、未知 ID 回调、结束结果保持、成功回调与实际活动表收尾的区别、同步 UI 通知及其超时隔离、失败任务离开活动列表，以及此前的批量记录和分类回归。
- 生产缓存与复制代码通过真实主机文件/SHA-1 测试：临时读锁、复制锁、发布锁恢复且不重新下载；永久错误不循环；锁持续时有上限；取消停止重试；坏文件仍拒绝发布。
- 页面、首次语言初始化、官方安装计划、入口和重定位回归通过。

Windows 和原下载引擎的 API 在这些测试中使用替身；没有实测用户环境的失败率、真实下载中心排版和真实文件锁行为。请先作为测试版验证，再更新 GitHub 正式发布。此前 360 告警尚未解决。
